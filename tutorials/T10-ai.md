# T10 AI coding：帮助理解、实现并留下可信证据

## 1. 为什么学与边界

AI（Artificial Intelligence，人工智能）可以加速查找、设计和生成测试，也会在协议、定点、并发和SIMD上给出貌似合理的错误。三个月必学本章：每次应用先写自己理解的契约，再用AI提出候选，最终用工具和参考验证。部门能力等级、批准工具和资料输入边界由主管确认；这里的建议练习不是部门标准。

前置至少T01接口、T03测量。尚未批准内部资料输入时用合成代码或非敏感的抽象接口练习；即使本地工具也先遵循公司规则。不自行上传内部代码、dump、日志或客户案例。

## 2. 统一工作流与记录结构

人写目标、输入输出、假设和验证方法→AI解释/候选→人逐段复述→编译/参考/边界检查→审阅差异→项目回归和性能→保存采纳或拒绝理由。AI回答不是证据；能复现的命令、结果、版本与人工解释才是证据。

记录字段：任务ID、工具/模型版本（若可得）、批准范围、输入摘要、提示词、关键回答、采纳/修改/拒绝、验证命令/结果、发现错误、人的解释、评审意见。无需无差别保存敏感全文，按部门留痕方式记录。

## 3. 六类可直接使用的提示词

代码理解：

```text
这是获准分享的合成C++函数。先解释输入输出、长度单位、内存布局、
所有权、整数范围与调用前提。按事实/推断/缺失信息分别列出。
不要改代码。给我3个问题，让我证明自己理解，再给反例和答案。
```

设计：

```text
我已经写出如下标量契约和测试参考……目标是在支持SVE的ARM上优化。
请提出两个有限范围方案，比较访存、尾部、数值、接口影响。
不要假设固定向量长度或SVE2；列出必须从真实代码/硬件确认的信息。
给出验证步骤，性能只列测量方案，不虚构收益。
```

实现：

```text
按此已确认接口实现VLA SVE循环。逐句解释数据类型、lane、predicate、
标量对应和inactive lane使用。保留精确数值规则及合法边界。
禁止擅改接口、加fast-math、restrict或默认输入对齐；未知条件先标明。
```

测试：

```text
先从契约生成测试矩阵，再写测试。oracle由独立标量规则提供。
覆盖零长度、短输入、向量长度±1、非对齐、极值、负数、饱和阈值±1、seed。
区分已运行结果和预期；指出哪些测试可能因额外buffer空间漏掉过读。
```

性能：

```text
下面是同CPU同配置的多次原始数据和计时范围……请计算中位数、离散度、
速度倍数与耗时下降，指出噪声/频率/cache/统计范围的限制。
仅提出可验证瓶颈假设。不要从函数收益推断目标多小区达标。
```

定位：

```text
这是获准的脱敏失败摘要、版本和最小输入……按配置/接口/算法/性能/Timing
列假设，每个附能排除它的最小检查。先核时间域和数值契约。
不要直接补丁掩盖症状；指出还缺的证据以及最早分歧点。
```

## 4. 验证AI输出：四个高风险点

定点：确认中间位宽、舍入、负数移位、饱和及运算顺序。让AI写的“看似等价”版本用极值反例推翻；最终数学规则由人/模块owner确认。

SIMD：核对真实intrinsic存在、ISA要求、元素类型、lane顺序、尾部、别名和有效长度。能编译不保证能在目标CPU运行，能运行不保证和标量一致；检查汇编及目标硬件。

并发：画数据所有权和happens-before（先行发生）关系；atomic只保护相应对象，volatile不解决竞争。用TSan、真实并发回归和评审，不能接受“多测几次没崩”的解释。

性能：先检查参考版本有无自动向量化、LTO消除、输出未消费、频率/cache变化，AI不能代替实测。系统指标必须在公司目标配置验收。

## 5. 操作实验与代码阅读

读取labs标量加法，先自己用10行文字解释，再用“代码理解”提示词比对。请AI找饱和窄化和SVE写死长度的潜在问题；自己手算边界并运行已提供check。提示词生成的变更只在独立练习副本评估，不直接替换项目代码。

进行三类应用：理解、设计、测试/定位，各写一条记录；至少保留一次“拒绝AI建议”的理由，例如AI建议用普通整数加法代替饱和或先假设32字节对齐。若AI没有实际给出错误，不能捏造纠错案例，可用明确标注的预设错误练习，并另找真实项目应用证据。

读AI代码时从契约反推，而非从注释相信代码：找最长读取、所有写入、类型转换和尾部；检查新增分支和删除错误处理。自己必须能解释关键循环，不会解释就回读基础并请求更小示例。

## 6. 常见问题与方法

AI引用不存在的条款：回到官方PDF核版本/编号。编译成功即提交：缺正确性、ISA和回归证据。AI加“优化”参数后加速：核fast-math、容限、架构和自动向量化变化。大量生成测试都绿：可能oracle和实现复制同一错误，需独立参考/手算反例。

不要按AI生成行数评价能力。建议证据是能定义问题、识别错误、验证、解释结果和正确使用批准工具，最终部门标准待确认。

## 7. 自测与三级标准

问：AI给出2倍收益表能填报告吗？答：只能作为假设，真实结果必须实测。问：代码理解用途可以跳过保密规则吗？答：不可以。问：不会解释核心SIMD但测试过了算独立吗？答：不算完整独立证据。

入门：写带契约的提示词并识别未知条件。应用：完成三类合成练习、验证和拒绝/修正记录。独立：在批准真实任务中从理解到验证留证，能人工讲解原理并满足部门确认标准。
