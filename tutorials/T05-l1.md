# T05 L1架构、Timing与PUSCH代码追踪

## 1. 任务关系与前置

实时软件不能只保证算法结果正确，还要在结果被使用前完成。三个月必学目标链路、线程、buffer和期限；全系统调度器实现、所有通道、深度NUMA调优后续深入。前置T02的frame/slot、T01的接口和生命周期。

Timing tick（时序节拍）是项目用于驱动处理的事件或时钟粒度，不自动等于一个slot或symbol。项目可能按symbol调度、按slot聚合或多级流水，必须读真实文档。

## 2. 接收链与功能切分

通用链路：L2调度参数→对应slot的数据到达→资源提取→DM-RS处理/信道估计→MIMO检测/均衡→软解调→解扰/速率恢复/HARQ合并→LDPC（Low-Density Parity-Check，低密度奇偶校验）解码→CRC→结果上报。算法选型不是3GPP强制指定的接收实现。

如果项目7-2x切分，O-RU（O-RAN Radio Unit，无线单元）通常负责上行低PHY如CP移除/FFT，O-DU（O-RAN Distributed Unit，分布式单元）收到频域IQ并做高PHY；天线/波束处理依RU类别及项目配置。其他切分可能收到时域IQ，所以不能给所有vDU（virtualized Distributed Unit，虚拟化分布式单元）入口都画FFT。

DMAP/DEC等内部名称不指定其位置。读设计后把实际模块填在通用功能上；不从名字猜“就是解映射/解码”。

## 3. 时序与数据结构

用一个slot描述事件：配置到达t_cfg，IQ最后必需片段到达t_iq，任务开始t_start、结束t_end，结果发送t_report，项目规定deadline为t_deadline。需要同时检查数据就绪、依赖完成、调度等待、执行及上报。margin（余量）=deadline-report；具体参考点由项目定义，不能把所有任务都定为slot结束。

教学例、不是公司指标：slot为0.5ms，但处理参考点允许某结果在特定时刻输出；某任务计算从80μs降到60μs，若一直等待IQ至400μs才启动，它的系统收益受等待和剩余路径限制。跨slot流水的期限可能不是相同slot结尾，必须从接口/规范/项目文档确认。

教学上下文结构：

```cpp
struct RxContext {
    unsigned cell; unsigned frame; unsigned slot;
    unsigned ue; unsigned harq_process;
    const void* iq; std::size_t iq_bytes;
    void* output; std::size_t output_bytes;
};
```

它只说明读字段的思路，不是项目API或可直接使用的PHY接口。真实结构还应包含资源、格式、有效期和状态。队列里的指针只能在消费者完成前不被归还/复用。多小区共享线程或buffer池时，同一slot编号不能作为全局唯一key。

## 4. 代码阅读与追踪方法

从已通过用例的入口开始，找到配置解析/注册/回调，再追目标函数。给每一步写“线程名/TID（Thread Identifier，线程标识）、输入buffer、输出buffer、生产者、消费者、释放时刻、依赖、期限”。同步调用和入队异步调用要分开，函数调用图不是完整任务图。

```bash
rg -n '目标入口|目标函数' src tests
rg -n 'enqueue|dispatch|callback|register|thread' path/to/module
rg -n 'alloc|free|release|pool|refcount' path/to/module
```

只有从代码/文档证实的点标“事实”。对宏选择、多架构分支、内联调用、硬件加速接口核对实际构建。用`git rev-parse HEAD`记录公司版本（如果仓库是Git），截图不能替代版本与路径。

## 5. 可操作实验

先做纸面任务表：为一个已通过单小区用例列配置、IQ、目标函数、解码和上报的时间。再由项目支持的Trace或log取真实事件，不随意在生产热路径加printf。用`ps -L -p "$TASK_PID" -o pid,tid,psr,comm`和批准的工具观察线程；TASK_PID由学习者填实际进程。

离线把时间表放CSV，用`python3 labs/timing_check.py your_events.csv`检查每条记录的queue/compute/report和margin。脚本用单一参考时钟的教学格式，输入前先完成时间域转换。运行`python3 labs/timing_check.py labs/timing_example.csv`只分析合成数据，不能登记成项目时序通过。

预期：区分等待时间、计算时间和报告延迟；负margin标记为超期。完成：真实追踪一个slot或说明无权限，图有线程及所有权，而非只有算法盒子。

## 6. 常见问题与分析

用错buffer：核对slot/cell/UE key、生产消费时序、复用和长度。任务计算快但结果晚：查队列等待、依赖、IQ晚到或上报阻塞。多小区才出错：查共享状态和资源争用；单小区通过不证明并发安全。Trace时间逆序：可能跨核时钟、异步写log、不同时间域，先校准再下结论。

插桩导致超期：用项目低开销机制，独立记录插桩版本，正式性能恢复一致配置。L2/L1参数迟到、IQ迟到、算法慢、线程未调度是四类不同问题，用各阶段时刻区分。

## 7. 自测与标准

问：tick一定等于slot吗？答：不是，项目定义。问：函数图足够解释实时运行吗？答：还需队列、线程、依赖和buffer生命周期。问：所有DU都自己FFT吗？答：取决于切分和实际入口。

入门：解释接收流程和时间点。应用：完成一个slot的调用/任务/所有权图与离线时间计算。独立：从真实Trace定位一个等待或期限问题，给出可复现证据和负责边界，导师确认项目映射。
