# T07 测试与问题分析：建立独立工作闭环

## 1. 为什么学与前置

测试不是只运行脚本，而是知道覆盖了什么、什么算通过、失败如何复现。三个月必学本章；大规模自动测试平台、完整链路仿真后续深入。前置为T01契约、T02参数、T03测量。

贯穿案例代号P01：一个导师确认的PUSCH热路径SVE优化。真实目标待确认；教学向量加法只训练方法，不代表完成P01。P01从需求、基线、设计、实现、故障、回归、系统验证到报告使用同一证据索引。

## 2. 用例与接口

unit test（单元测试）验证局部函数，integration test（集成测试）验证接口/模块组合，regression（回归）检查原能力未被破坏，system test（系统测试）验证目标运行。golden/reference（参考结果）必须有来源和版本；同时改两份实现得到相同结果不证明正确。

每个用例记录：ID、目的、输入和配置、期望/容限、命令、版本、输出、判定和原始证据。浮点按绝对/相对误差及下游影响定义容限；整数按bit-exact（逐bit一致）或项目数值契约，禁止为了通过临时放宽。CRC一致不能替代全部中间数值检查，局部微差也需解释系统影响。

| 层级 | P01最小矩阵 | 证据 |
|---|---|---|
| 函数 | n=0、1、向量长度±1、非倍数、典型/最大合法长度、合法非对齐 | 差分、检查器、失败最小输入 |
| 数值 | 正负、极值、零、舍入/饱和阈值±1、随机seed | 参考规则、输出/误差 |
| 模块 | 支持的资源/MCS/层/参考配置、HARQ/RV、实际I/O格式 | 既有参考用例、CRC/中间数据 |
| 回归 | 本变更影响路径及x86/ARM保留分支 | 同版本配置矩阵与结果 |
| 系统 | 单小区、确认目标多小区、稳定负载、时序/正确性/丢包 | 完整配置、原始Trace/log、统计 |

不是穷举所有参数组合；先依据变更触及的分支和公司回归要求选代表和边界，再让导师确认覆盖。XC/DRT/LLS是内部工具/方法名称待确认，为每个登记启动、配置、判定及错误码，不猜测角色。

## 3. 执行与失败定位流程

保存旧版本、同输入和命令，先重复失败，再检查环境。找到最早异常阶段，而不是盯最终CRC：配置→资源/参考→检测/LLR→速率恢复/HARQ→解码→上报。每次只改变一项，二分缩小输入范围，保存seed。对配置、接口、算法、性能、Timing分别提出假设和验证动作。

配置问题看参数/版本、合法范围；接口问题看布局/单位/生命周期；算法问题看中间值和数值契约；性能问题看耗时/负载；Timing问题看数据就绪、等待和deadline。环境问题如工具链、CPU能力、文件权限不应伪装成算法缺陷。

## 4. 代码阅读方法与操作练习

在独立实验运行`demo check`，阅读main中0—257长度/不同偏移、随机输入和独立参考。阅读向量尾部是否可能访问n之外。修改实验副本的尾部条件使n=13暴露失败，只用于练习，不改项目代码；记录最小反例，再恢复正确版本。可用独立ASan构建验证精确边界，测试数组必须足够小且真实尾端不能藏在大buffer内部。

项目执行使用导师提供脚本，当前只给占位例：

```bash
# 先填真实脚本/配置；以下不是可直接运行的公司命令
# <approved_runner> --config <case_config> --output <evidence_dir>
```

占位之所以保留，是内部资料缺失；教程实验命令在labs可执行。收集配置hash、构建ID、输入hash及日志。失败后用同版本重跑并比较旧版本；回滚应遵循团队流程，不把测试版本部署到未授权环境。

## 5. P01完整记录示例（预期流程）

需求：减少目标热点耗时，最终以公司多小区阈值验证。baseline：先通过已有用例，保存热点占比。设计：写数据与数值契约，导师评审。实现：SVE首版；若n非倍数失败，先用小输入和独立参考定位predicate/长度，再修复并回归。性能：同平台交替测旧/新，随后单小区和目标多小区。总结：写收益、剩余等待/热点和未满足指标。

这是预期工作路线，非已经发生的缺陷或收益。实际案例必须用真实issue、版本、原始输入和评审记录替换，不能把预设反例包装为真实业务问题。

## 6. 常见问题

用例全绿但系统错：覆盖可能没包含多小区共享状态、尾部或真实格式。无法复现：查输入未保存、异步状态、seed、频率和版本。随机失败：查buffer复用、越界、数据竞争、HARQ状态，不先随机多加sleep。新旧都错：可能是原缺陷、输入错误或共同参考错误，继续定位，不能算新版本通过。

## 7. 自测与完成标准

问：放宽误差使测试绿可以直接接受吗？答：先解释误差来源及系统影响，由数值契约owner确认。问：函数通过证明多小区吗？答：不证明。问：失败记录最少保存什么？答：版本、配置、输入/seed、命令、期望、实际、原始日志和重复性。

入门：区分四级测试及五类问题。应用：运行差分/边界、复现一个合成缺陷并写记录。独立：P01真实闭环由导师确认，测试记录能被他人复现，不能用练习替代真实问题证据。
